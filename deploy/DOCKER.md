# ikik-api Container Image

Official image:

```text
ghcr.io/ipanel/sliderapiv2
```

## Platforms

The GHCR workflow publishes one multi-platform manifest with:

- `linux/amd64`
- `linux/arm64`

Docker automatically selects the correct architecture.

## Tags

- `latest`: most recently published release image
- `vX.Y.Z`: immutable release tag generated by the Release workflow

For production, prefer a version tag:

```bash
docker pull ghcr.io/ipanel/sliderapiv2:vX.Y.Z
```

## GHCR publishing authorization

The workflow requests `packages: write` and normally publishes with the repository-scoped `GITHUB_TOKEN`. If `ghcr.io/ipanel/sliderapiv2` was originally created by another repository or by a personal token, GitHub may not grant this repository write access automatically and the push fails with `permission_denied: write_package`.

Preferred fix for the existing package:

1. Open the `sliderapiv2` package settings under the `ipanel` account.
2. Under **Manage Actions access**, add `ipanel/SliderAPIv2` with the **Write** role, or enable access inheritance from this repository.
3. Re-run the failed GHCR job.

The workflow also supports an explicit repository-secret fallback:

- `GHCR_TOKEN`: classic personal access token with `write:packages` (and `read:packages`) permission.
- `GHCR_USERNAME`: owner of that token, normally `ipanel`.

Configure both secrets together and do not commit either value to the repository. When both are absent, the workflow continues to use `GITHUB_TOKEN`; a partial configuration fails early with an explicit error.

## Recommended deployment

Do not run only the application container unless MariaDB and Redis already exist. Use the maintained Compose stack:

```bash
mkdir -p sliderapiv2 && cd sliderapiv2
curl -fsSL https://raw.githubusercontent.com/ipanel/SliderAPIv2/main/deploy/docker-deploy.sh | bash
```

On first install the script creates `.env` and generates secrets. On later runs it updates deployment templates while preserving the existing `.env` and persisted credentials. It refuses to replace credentials when data exists without `.env`. Full instructions are in `deploy/README.md`.

## Standalone container

For an existing MariaDB and Redis installation:

```bash
docker run -d \
  --name ikik-api \
  --restart unless-stopped \
  -p 8080:8080 \
  -v ikik_api_data:/app/data \
  -e AUTO_SETUP=true \
  -e SERVER_HOST=0.0.0.0 \
  -e SERVER_PORT=8080 \
  -e DATABASE_DRIVER=mysql \
  -e DATABASE_HOST=db.example.com \
  -e DATABASE_PORT=3306 \
  -e DATABASE_USER=ikik_api \
  -e DATABASE_PASSWORD="$DATABASE_PASSWORD" \
  -e DATABASE_DBNAME=ikik_api \
  -e REDIS_HOST=redis.example.com \
  -e REDIS_PORT=6379 \
  -e REDIS_PASSWORD="$REDIS_PASSWORD" \
  -e JWT_SECRET="$JWT_SECRET" \
  -e TOTP_ENCRYPTION_KEY="$TOTP_ENCRYPTION_KEY" \
  ghcr.io/ipanel/sliderapiv2:vX.Y.Z
```

`/app/data` must remain persistent. It contains the generated configuration and installation state used to select the full application router after first-time setup.

## Required configuration

| Variable | Purpose |
|---|---|
| `AUTO_SETUP=true` | Performs non-interactive first-time setup |
| `DATABASE_HOST`, `DATABASE_PORT` | MariaDB address |
| `DATABASE_USER`, `DATABASE_PASSWORD`, `DATABASE_DBNAME` | MariaDB credentials/database |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` | Redis connection |
| `JWT_SECRET` | Stable signing key across restarts |
| `TOTP_ENCRYPTION_KEY` | Stable encryption key for stored 2FA secrets |

Optional OAuth flows require explicitly supplied credentials:

```text
GEMINI_OAUTH_CLIENT_ID
GEMINI_OAUTH_CLIENT_SECRET
GEMINI_CLI_OAUTH_CLIENT_ID
GEMINI_CLI_OAUTH_CLIENT_SECRET
ANTIGRAVITY_OAUTH_CLIENT_ID
ANTIGRAVITY_OAUTH_CLIENT_SECRET
```

No OAuth secret is embedded in the image.

## Health check

```bash
curl -f http://127.0.0.1:8080/health
```

If `/health` works but `/api/v1/settings/public` returns 404, inspect startup logs. The service may be in setup-only mode because MariaDB/Redis initialization failed or `/app/data` is not writable.

## Local source build

From the repository root:

```bash
docker build -t ikik-api:local .
```

Or use the development Compose file:

```bash
cd deploy
docker compose -f docker-compose.dev.yml up --build
```

The canonical production Dockerfile is the repository-root `Dockerfile`; `deploy/Dockerfile` is kept synchronized for compatibility.
