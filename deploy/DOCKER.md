# ikik-api Container Image

Official image:

```text
ghcr.io/ipanel/sliderapiv2
```

## Platforms and tags

The GHCR workflow publishes one multi-platform manifest for:

- `linux/amd64`
- `linux/arm64`

Tags:

- `latest`: most recently published release image
- `vX.Y.Z`: immutable release tag generated by the Release workflow

For production, prefer a version tag:

```bash
docker pull ghcr.io/ipanel/sliderapiv2:vX.Y.Z
```

## Recommended SQLite deployment

New installations default to SQLite plus Redis:

```bash
mkdir -p sliderapiv2 && cd sliderapiv2
curl -fsSL https://raw.githubusercontent.com/ipanel/SliderAPIv2/main/deploy/docker-deploy.sh | bash
```

The SQLite database and generated setup state are stored under the persistent `data/` directory. New installations open the browser setup wizard with SQLite preselected. This is recommended for a single application instance. The published port binds to `127.0.0.1` by default so nobody on the network can claim the unauthenticated first-run setup. Complete setup locally (or through an SSH tunnel/reverse proxy), and set `BIND_HOST=0.0.0.0` only after access is protected.

To use MariaDB instead:

```bash
curl -fsSL https://raw.githubusercontent.com/ipanel/SliderAPIv2/main/deploy/docker-deploy.sh | bash -s -- --database mysql
```

The installer resolves the newest strict `vX.Y.Z` tag, downloads templates from that tag, and pins the image to the same tag. It preserves an existing deployment's database type, Compose file, credentials, and custom volume mappings, and rejects an automatic engine switch. Existing installations keep their current Compose file so runtime overrides and storage mappings are not silently changed. Never replace an existing MariaDB Compose file with the new default SQLite template; that is not a database migration and may omit the MariaDB service. Changing `DATABASE_DRIVER` or switching Compose files does not migrate existing data; back up and migrate explicitly before changing engines. See [README.md](README.md) for full backup, upgrade, setup-wizard, and troubleshooting instructions.

New installations store `COMPOSE_PROJECT_NAME=sliderapiv2` in `.env` so Docker named volumes keep a stable identity. For old named-volume deployments the updater discovers the original project label; if it cannot do so safely, it stops and asks you to restore/set the original value. Deployments using `COMPOSE_FILE`, an override file, or any manually named `docker compose -f ...` entry point must be updated manually with the exact same Compose file list. The one-click updater only manages a directory whose selected stack is stored as `./docker-compose.yml`; it checks existing container labels and refuses ambiguous directories containing another YAML Compose stack.

If an older Compose file still passes connection settings to `ikik-api` as runtime `DATABASE_*` or `REDIS_*` variables, the updater stops before recreating containers. Rename only those connection entries to `SETUP_DATABASE_*` and `SETUP_REDIS_*`; keep pool/tuning variables and the Redis service's own `REDIS_PASSWORD` unchanged. Otherwise runtime environment variables would continue overriding `/app/data/config.yaml` after restarts.

## Standalone SQLite container

When using `docker-compose.standalone.yml`, copy `.env.standalone.example` to `.env`; do not reuse the bundled-stack `.env.example`. Existing standalone deployments must also replace a legacy `DATABASE_HOST=mariadb` value with an address reachable from the application container.

Redis is still required. Assuming Redis is reachable as `redis.example.com`:

```bash
docker run -d \
  --name ikik-api \
  --restart unless-stopped \
  -p 8080:8080 \
  -v ikik_api_data:/app/data \
  -e AUTO_SETUP=true \
  -e DATA_DIR=/app/data \
  -e SERVER_HOST=0.0.0.0 \
  -e SERVER_PORT=8080 \
  -e SETUP_DATABASE_DRIVER=sqlite \
  -e SETUP_DATABASE_PATH=ikik-api.db \
  -e SETUP_REDIS_HOST=redis.example.com \
  -e SETUP_REDIS_PORT=6379 \
  -e SETUP_REDIS_PASSWORD="$REDIS_PASSWORD" \
  -e SETUP_REDIS_DB=0 \
  -e JWT_SECRET="$JWT_SECRET" \
  -e TOTP_ENCRYPTION_KEY="$TOTP_ENCRYPTION_KEY" \
  ghcr.io/ipanel/sliderapiv2:vX.Y.Z
```

Do not run multiple application replicas against the same SQLite file.

## Standalone MySQL/MariaDB container

For an existing MySQL/MariaDB and Redis installation:

```bash
docker run -d \
  --name ikik-api \
  --restart unless-stopped \
  -p 8080:8080 \
  -v ikik_api_data:/app/data \
  -e AUTO_SETUP=true \
  -e DATA_DIR=/app/data \
  -e SERVER_HOST=0.0.0.0 \
  -e SERVER_PORT=8080 \
  -e SETUP_DATABASE_DRIVER=mysql \
  -e SETUP_DATABASE_HOST=db.example.com \
  -e SETUP_DATABASE_PORT=3306 \
  -e SETUP_DATABASE_USER=ikik_api \
  -e SETUP_DATABASE_PASSWORD="$DATABASE_PASSWORD" \
  -e SETUP_DATABASE_DBNAME=ikik_api \
  -e SETUP_DATABASE_SSLMODE=disable \
  -e SETUP_REDIS_HOST=redis.example.com \
  -e SETUP_REDIS_PORT=6379 \
  -e SETUP_REDIS_PASSWORD="$REDIS_PASSWORD" \
  -e SETUP_REDIS_DB=0 \
  -e JWT_SECRET="$JWT_SECRET" \
  -e TOTP_ENCRYPTION_KEY="$TOTP_ENCRYPTION_KEY" \
  ghcr.io/ipanel/sliderapiv2:vX.Y.Z
```

`/app/data` must remain persistent in both modes. It contains generated configuration and the installation lock in addition to SQLite data when SQLite is selected.

## Browser-based initialization

New Compose installations default to `AUTO_SETUP=false` and launch the web setup wizard. The wizard defaults to SQLite and also offers MySQL. The selected database must be reachable from the container and match the infrastructure you started: use Redis host `redis`; with a bundled MariaDB stack, select MySQL and use host `mariadb` plus the credentials stored in `.env`. Set `AUTO_SETUP=true` before first startup only for unattended environment-based setup. Setup creates `config.yaml` and `.installed` under `/app/data`.

## Required configuration

| Variable | Purpose |
|---|---|
| `AUTO_SETUP` | `true` for unattended environment-based setup; `false` for the web wizard |
| `SETUP_DATABASE_DRIVER` | `sqlite` or `mysql` for unattended setup |
| `SETUP_DATABASE_PATH` | SQLite filename/path under `DATA_DIR` |
| `SETUP_DATABASE_HOST`, `SETUP_DATABASE_PORT` | MySQL/MariaDB address |
| `SETUP_DATABASE_USER`, `SETUP_DATABASE_PASSWORD`, `SETUP_DATABASE_DBNAME`, `SETUP_DATABASE_SSLMODE` | MySQL/MariaDB credentials/database |
| `SETUP_REDIS_HOST`, `SETUP_REDIS_PORT`, `SETUP_REDIS_PASSWORD`, `SETUP_REDIS_DB` | Redis connection used during setup |
| `JWT_SECRET` | Stable signing key across restarts |
| `TOTP_ENCRYPTION_KEY` | Stable encryption key for stored 2FA secrets |

The legacy `DATABASE_*` and `REDIS_*` connection names are accepted only as a backward-compatible setup fallback. Prefer `SETUP_*`. Do not define both forms of the same connection key: the application rejects that configuration before startup so runtime environment variables cannot override values written to `/app/data/config.yaml`.

Optional OAuth flows require explicitly supplied credentials:

```text
GEMINI_OAUTH_CLIENT_ID
GEMINI_OAUTH_CLIENT_SECRET
GEMINI_CLI_OAUTH_CLIENT_ID
GEMINI_CLI_OAUTH_CLIENT_SECRET
ANTIGRAVITY_OAUTH_CLIENT_ID
ANTIGRAVITY_OAUTH_CLIENT_SECRET
```

No OAuth secret is embedded in the image.

## Health check and setup-only mode

```bash
curl -f http://127.0.0.1:8080/health
```

If `/health` works but `/api/v1/settings/public` returns 404, inspect startup logs. The service may be in setup-only mode because database/Redis initialization failed or `/app/data` is not writable.

## Local source build

From the repository root:

```bash
docker build -t ikik-api:local .
```

SQLite development stack:

```bash
cd deploy
docker compose -f docker-compose.dev.yml up --build
```

MariaDB development stack:

```bash
cd deploy
cp .env.example .env
# Edit .env and set non-empty MARIADB_ROOT_PASSWORD and MARIADB_PASSWORD values.
chmod 600 .env
docker compose -f docker-compose.dev.mysql.yml up --build
```

## GHCR publishing authorization

The workflow requests `packages: write` and normally publishes with the repository-scoped `GITHUB_TOKEN`. If the package exists but is not linked to this repository, grant `ipanel/SliderAPIv2` **Write** access in the package's **Manage Actions access** settings.

The workflow also supports both repository secrets together:

- `GHCR_TOKEN`: classic PAT with `write:packages` and `read:packages`
- `GHCR_USERNAME`: token owner, normally `ipanel`

If the old `ghcr.io/ipanel/sliderapiv2` package was deleted, re-run the workflow. It should recreate the package under the current repository; no image name or Compose change is needed.
